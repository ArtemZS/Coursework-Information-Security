# Обмен изображениями и текстом

Курсовой проект на Python 3.14 с графическим интерфейсом Tkinter. Два экземпляра приложения обмениваются изображениями PPM или JPEG и текстовыми сообщениями по TCP.

## Запуск

Нужны Python 3.14 с Tkinter, `uv` и `just`. Выполните команды из каталога проекта.

~~~powershell
just setup
just test
~~~

Откройте два терминала и запустите по одному экземпляру в каждом.

~~~powershell
just run
~~~

~~~powershell
just run --listen-port 9002 --peer-port 9001
~~~

Первое окно слушает порт 9001 и отправляет на 9002, второе использует обратную пару. По умолчанию приём доступен на `127.0.0.1`. Для работы в локальной сети запустите экземпляр с `--listen-host`, указав его IPv4-адрес, и введите в интерфейсе IP-адрес и порт получателя.

1. В первом окне введите логин и пароль длиной от 8 символов, затем нажмите «Создать аккаунт». При повторном запуске используйте кнопку «Войти».
2. Оставьте второе окно в гостевом режиме. В первом откройте изображение, введите текст, выберите AES-256-GCM и нажмите «Отправить».
3. Проверьте имя отправителя, изображение и текст во втором окне. Повторите отправку с ChaCha20-Poly1305.
4. Для проверки обратного направления войдите во втором окне и отправьте сообщение на порт 9001. Учётные записи хранятся в `.data/accounts.sqlite3`. Для отдельных баз передайте `--db` каждому экземпляру.

Для проверки PPM можно сохранить следующий текст в файл `example.ppm`.

~~~text
P3
3 2
255
255 0 0     0 255 0     0 0 255
255 255 0   0 255 255   255 0 255
~~~

## Учётные записи и протокол

- SQLite хранит логин, отдельную случайную соль и хэш пароля PBKDF2-HMAC-SHA256 с 600 000 итераций.
- Получатель отправляет открытый ключ RSA-2048 при установлении TCP-соединения. Отправитель создаёт случайный 256-битный симметричный ключ для каждого сообщения и передаёт его, зашифровав RSA-OAEP с SHA-256.
- Логин отправителя, текст UTF-8 и байты изображения упаковываются в двоичное сообщение. Отправитель добавляет CRC-32 и шифрует пакет блочным AES-256 в режиме GCM или поточным ChaCha20 с Poly1305. Получатель проверяет тег шифра, CRC-32 и формат изображения перед подтверждением приёма.
- Обмен открытыми ключами в учебном канале выполняется без проверки подлинности ключа. Имя в сообщении берётся из локальной сессии отправителя и не является доказательством его личности для получателя.
- Размер изображения ограничен 16 МиБ и 16 млн пикселей. Максимальная длина текста составляет 256 КиБ в UTF-8. В окне доступны последние 20 входящих сообщений до закрытия приложения.
